# Conformance fixtures

Language-neutral fixtures let another implementation (for example a future
Swift port for Game of Mods) run the same rules tests. All mechanics are
integers; dice are explicit.

| Fixture | Contents |
|---|---|
| `tests/fixtures/rules/creation_cases.json` | Standard creation cases with validity and required error codes. |
| `tests/fixtures/rules/resolution_cases.json` | Check inputs, dice and expected total, margin and band (incl. the brief's 3+2 vs 13 example and Branch C). |
| `tests/fixtures/rules/probability_calibration.json` | 489 enumerated rows (facet/skill splits × all tiers × modifiers × costly on/off, plus push/resolve scenarios) and the 5+3 vs 14 correction fixture. Generated by an independent Python implementation (`tools/generate_rule_fixtures.py`). |
| `tests/fixtures/characters/codec_cases.json` | Schema-valid characters that the rules reject (unknown skill/talent). |
| `tests/fixtures/schemas/<type>/{valid,invalid}` | Positive and negative fixtures for characters, actions, packs, requests, AI proposals, events and saves. Valid event and save fixtures are exported from the implementation (`tools/export_fixtures.gd`). |
| `examples/night_market/fixtures/walkthrough_mara.json` | The mandatory scripted walkthrough with its three branches. |

The source calibration rows from the rules draft were not available; the
calibration table is computed by exact enumeration and must be cross-checked
against the source draft when it is added (see `rules-v0.1.md`).

Game of Mods is an intended integration, not a conformant implementation,
until an actual integration passes these fixtures.

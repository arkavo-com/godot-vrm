## M0 — Contracts

Project skeleton, copied implementation brief, rules placeholder, decision
log, JSON Schemas for every transport type with positive and negative
fixtures, typed DTOs, language-neutral rule fixtures (generated by an
independent Python reference implementation).

*Limitation:* the source rules draft was not available; `rules-v0.1.md` is a
placeholder and talent behavior is recorded as decisions marked *pending
source*.

## M1 — Pure core (T01–T10)

Resolver, modifiers, exact probability, dice sources, creation validation,
authoring Resources. The 5+3 vs 14 correction fixture (3/7/20/6 of 36;
27.78% failure without costly success) and 489 calibration rows match the
independent reference. Tests: `test_core_rules.gd` plus session-level T04,
T07–T10 in `test_session.gd`.

## M2 — Session (T11–T12, T14–T24)

Preview/commit/choose/abandon, registry, operation allowlist, journal of
low-level ops, memory and file stores (atomic replace with `.bak` recovery),
replay with integrity checks, retry locks, idempotency, injected persistence
and effect failures. Tests: `test_session.gd`, `test_ai.gd` (T23).

## M3 — Content (T13, T25–T28)

Six noncombat talents, identity triggers, progression and respec, admission,
portable codec with limits and migrations. Tests: `test_talents.gd`,
`test_progression.gd`, `test_import.gd`, `test_transport.gd`.

## M4 — Editor (T29)

Inspector panels for characters, actions and talents with undoable edits and
copy-on-write of shared sub-resources; validation dock with field navigation
and blocked export; probability dock. Tests: `test_editor.gd` (models) and
the real-editor self-test (enable/disable cycles without duplicate UI or
settings changes, one inspector panel, undo/redo through
`EditorUndoRedoManager`).

*Limitations:* not inspected manually at normal or high display scaling;
Godot's own project export cannot be blocked from a plugin (D-026).

## M5 — Playable MVP (T30)

Night Market Delivery with three routes, the stranded passenger identity
trigger, a deadline, a milestone and a second scene with retained
consequences; save/load/reset; offline fake-AI suggestions; debug-only fixed
dice. Tests: `test_demo.gd` (all routes, Mara's branches A/B/C with
save/reload during the offered choice, passenger trigger, consequences, reset,
fake AI flow, UI smoke test). Screenshots in `images/` were captured from the
running demo under Xvfb.

## M6 — v0.1 release (C01–C04)

Optional combat package with Bodyguard and Last Reserve (all eight source
talents registered when installed), release archives, documentation and CI.
Tests: `test_combat.gd`.

*Limitations:* combat details left open by the brief are implementation
decisions (D-016 – D-018), pending the source draft.

## Remaining known limitations

* Source rules draft missing; every *pending source* decision needs review.
* Only Linux x86_64 tested (Godot 4.6.3 and 4.7.2). No macOS/Windows runs, no desktop export smoke
  tests, no gameplay export test with the plugin disabled (export templates
  were not available).
* No manual editor UX review.
* Licensing awaits owner approval; nothing has been published.
* Godot Asset Library route and AI-disclosure policy not checked.
* Combat encounters are not persisted mid-fight; results are written back to
  the session as one batch at the end.

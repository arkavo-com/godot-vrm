# Implementation decisions

Engineering choices that close gaps in the implementation brief. None of them
claims to be existing Game of Mods behavior. Items marked **pending source**
must be reconciled with the source rules draft (`rules-v0.1.md` is a
placeholder; see its header) before FACETS is described as conformant.

| ID | Decision | Why |
|---|---|---|
| D-001 | Baseline **Godot 4.6.3-stable** (official Linux x86_64 build, SHA-512 pinned in CI). **4.7.2-stable** is an additional tested version, run in CI. No other version is claimed. | Brief §1: target 4.6 as the initial baseline and pin an exact stable patch (4.6.3 was the latest 4.6 patch on 2026-10-07); test another stable version only when claiming it. 4.7.2 was the latest stable release on that date and passes the full pipeline. |
| D-002 | The six noncombat and two combat talents are implemented from the brief's one-line summaries (§3.4, §9). Their prerequisite values (e.g. Second Look needs Investigation 1, Steady Voice needs Empathy 3) are authored content in `.tres` files. **Pending source.** | The source §6 was not supplied. |
| D-003 | `FacetsActionRequest` carries two optional fields beyond the brief's list: `talent_ids` (declared talent use, currently only `core.second_look`) and `evidence_id` (Second Look's alternate evidence). | Second Look needs an alternate authored evidence source chosen by the player. |
| D-004 | Every state change is journaled as low-level ops (`set` with before/after, `append`, `remove`, `add_actor`, `note`). Replay applies these ops and checks every `before` value; it never consults dice or content scripts. | Brief §6: replay uses recorded dice and ordered effects; corrupt sequences stop with actionable errors. |
| D-005 | While a check or identity choice is pending, state-changing commands are rejected with a retryable `PENDING_DECISION` error; the host (or UI) queues and retries them. Previews are also refused while pending. | Brief §6.5 allows the default session to hold the revision locked; queueing at the host keeps the session API synchronous. |
| D-006 | Decision order is Resolve → costly offer → strong benefit. Resolve is offered whenever it is legal and the current band is not already strong success; the offer shows the resulting band (it may not change it). | Brief §6.4. Offering Resolve at strong success could never matter. |
| D-007 | Abandonment declines Resolve and costs, keeps Push paid, and chooses a strong benefit only if the action declares `default_benefit_id` (which may not require consent); otherwise it returns `DECISION_REQUIRED` and the event stays pending. | Brief §6.6. |
| D-008 | Retry locks key on actor + objective + approach + fingerprint. The fingerprint contains only tools the action lists (required, useful or substitutes), the helper, and a host-authorized objective epoch. World revision is excluded. Evidence changes unlock only through Second Look. | Brief §6 "Retry locks"; prevents irrelevant tools or rephrasing from unlocking retries. |
| D-009 | Standard admission uses the brief's stable greedy proposal; preferred points are allocated up to the preference first, leftovers in the same order up to the cap. Talents from non-core packages are only admitted when explicitly preferred. | Brief §3.4 implementation decision. |
| D-010 | Hard refusals are world data (`refusals: {npc: [topics]}`). `npc.grant` on a refused topic records a `refused` note and changes nothing, on every dice outcome. `npc.disposition` may only target NPCs, so no check ever writes a player character's beliefs. | T24. |
| D-011 | Standard conditions: Overwhelmed (−1 all checks; no push, no reactions, limited combat turn), Injured (−1 physical), Incapacitated (cannot act or react, no move), Shaken (−1 Empathy/Tenacity), Restrained (−2 physical, no move). **Pending source** for Shaken and Restrained. | The brief names Overwhelmed, Injured and Incapacitated; a small standard set was needed for authoring. |
| D-012 | "Physical" checks are those using Force or Agility. | Brief §9 "Injured (−1 physical)" without a definition. |
| D-013 | An identity disadvantage is *material* if applying it changes state. A trivial duplicate (nothing changes) awards 0. The award key `identity:<actor>:<scene>` is recorded even when the amount is 0 at the Resolve cap. | Brief §3.3 and T12. |
| D-014 | Field Engineer: one substitution per scene; the consumable is consumed at commit; object flags set by the action's success effects are reverted to their previous values at scene end. **Pending source.** | Brief §3.4 summary. |
| D-015 | Steady Voice: a fear setback is strain inflicted by an action flagged `fear` in the current scene. Using it is the actor's action (recorded as `actions:<scene>` usage outside combat). **Pending source.** | Brief §3.4 summary. |
| D-016 | Combat: an Overwhelmed actor's turn is limited to a move *or* an action; Last Reserve restores one normal turn per scene. **Pending source.** | The brief says Last Reserve "permits one normal turn while Overwhelmed", implying a limited turn. |
| D-017 | Combat details: ranged weapons reach the same or an adjacent zone with line of sight; long weapons reach any visible zone; cover applies to ranged and long attacks only; ammunition must be carried but is not consumed (detailed inventory is deferred); medicine needs supplies (`item.med_kit`), which are not consumed, and uses Sense or Cunning + Medicine. **Pending source.** | Brief §9 leaves these open. |
| D-018 | Bodyguard is declared with the attack (`interceptor_id`); the reaction is spent only if the attack hits. The defense is the original target's; the interceptor's armor applies. One interception per hit, never chained. | Brief §9 implementation decision on ordering/chains. |
| D-019 | Quiet Hands adds a talent-authored "leave no trace" option on strong successes with Stealth or Sleight; Bargain Maker adds the action's listed lesser concessions on strong Influence successes. Either *replaces* the normal strong benefit and is limited to once per scene. **Pending source.** | Brief §3.4 summaries. |
| D-020 | Second Look requires an existing retry lock (a failed attempt), an alternate evidence source listed on the action, unused for that objective, and once-per-scene usage; the extra interval advances the world clock by the talent's `interval`. The new attempt draws new dice. | Brief §3.4 "not a free unchanged reroll". |
| D-021 | Trail Reader reveals the first fact listed in `revealable_facts` that exists, has a non-empty `evidence_id`, is `trail_permitted` (default true) and is not already known. Once per scene. | Brief §3.4 summary. |
| D-022 | Milestones are deduplicated per actor by milestone ID and by underlying event key. | Brief §3.4. |
| D-023 | Raising a skill needs a host-granted training mark (`grant_training`). A facet purchase names the completed chapter it uses; each completed chapter allows one facet increase per actor. Respec of a rank refunds later ranks of the same skill or facet too; purchased talents whose prerequisites fail are refunded with it. | Brief §3.4. |
| D-024 | Up to 64 previews are cached in memory so stale tokens report `STALE_PREVIEW` rather than `UNKNOWN_PREVIEW`. Previews are not persisted; tokens are deterministic digests of session, principal, canonical request, action digest and revision. | Brief §6.1–6.2. |
| D-025 | The session defaults to a local host principal for single-player use. Hosts exposing a session to remote players or AI must pass explicit principals; the AI adapter always does. | Brief §5 "Authorization is out-of-band". |
| D-026 | Content export blocking is implemented in the validation dock's *Export content pack* action and in `FacetsValidationScanner.export_content`. Godot's own project export cannot be aborted from a plugin in 4.6, so it is not blocked. | Brief §7. |
| D-027 | Night Market: the delivery window closes after clock 3; each gate action costs 1; hearing Tamsin out costs 2 and marks the window missed. | Demo pacing. |
| D-028 | AI proposals are limited to 8 KiB, nesting 4 and 280 characters of display text. Observations are cached per observer and keyed by a digest of their perception-relevant content. | Brief §8. |
| D-029 | Saves keep the full event archive and request-ID map. `checkpoint()` compacts the journal. | Brief §6 save format. |
| D-030 | Percentages are rounded to two decimals independently. | Brief §7. |
| D-031 | The relationship modifier is authored per action as `{other_id, dimension}` and contributes +1 when that bond value is ≥1 and −1 when ≤−1. | Brief §3.2. |
| D-032 | A helper needs the approach's skill at rank ≥1 and must not be flagged `refuses_assistance`; risk is shared only through effects authored with `target: "helpers"`. | Brief §3.2. |
| D-033 | Godot's RNG state is saved as decimal strings (`seed`, `state`) to avoid 64-bit precision loss in JSON; RNG reproducibility is only claimed for 4.6.3. Debug-only fixed dice can be queued ahead of the RNG in demo builds. | Brief §6 "Godot's RNG is not a portability contract". |
| D-034 | The test runner installs a `Logger` and fails any test that raises an engine or script error, because GDScript runtime errors do not propagate to the caller. | Prevents silently passing tests. |
| D-035 | The editor self-test is a separate development-only plugin (`addons/facets_editor_selftest`) enabled temporarily by `tools/run_editor_selftest.sh`; it is excluded from release archives. | Editor classes cannot be instantiated outside the editor. |
